# Domain docs

## Before exploring

Read root `GLOSSARY.md` and ADRs in `docs/adr/` relevant to the work.

If these files are absent, proceed silently. Domain-modeling skills
create them when terms or decisions are resolved.

## Layout

This repo uses a single context:

- `GLOSSARY.md`: domain terminology.
- `docs/adr/`: architectural decision records.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed term is missing, reconsider the wording or note the gap
for `/domain-modeling`.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR, naming
the ADR and explaining why its decision should be reconsidered.
